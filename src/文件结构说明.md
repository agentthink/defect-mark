# 文件结构说明

本文档说明 `src` 目录下各文件夹的用途，方便后续继续扩展项目时保持结构一致。

## 总览

```text
src
├─ frontend
│  └─ maskflow-web
├─ backend
│  └─ maskflow-api
├─ ai
│  └─ sam-inference
└─ legacy
   ├─ static-frontend
   └─ python-api
```

## frontend

前端源码目录。

```text
frontend/maskflow-web
├─ src
│  ├─ App.vue
│  ├─ main.js
│  ├─ assets
│  └─ lib
├─ index.html
├─ vite.config.js
├─ package.json
├─ package-lock.json
├─ Dockerfile
└─ nginx.conf
```

用途：

- `src/App.vue`：当前主要页面和交互逻辑。
- `src/lib`：前端 API 请求、会话、通用工具。
- `src/assets`：前端运行必须使用的小型静态资源和样式。
- `Dockerfile`、`nginx.conf`：前端容器化部署配置。

不要放：

- 大模型文件。
- 原型截图集合。
- 后端接口实现。
- `node_modules`、`dist` 等生成目录。

## backend

业务后端源码目录。

```text
backend/maskflow-api
├─ Application
├─ Controllers
├─ Infrastructure
├─ Properties
├─ Program.cs
├─ MaskFlow.Api.csproj
├─ appsettings.json
├─ appsettings.Development.json
└─ Dockerfile
```

用途：

- `Program.cs`：应用启动、依赖注入、Swagger、Controller 注册。
- `Controllers`：HTTP 接口入口。接口分类、路由、请求响应适配放这里。
- `Application`：应用服务注册和后续业务用例编排扩展点。
- `Infrastructure`：本地存储、外部服务调用、基础设施实现。
- `appsettings*.json`：配置文件。

后续建议：

- 数据库替换时，把 EF Core、仓储实现放入 `Infrastructure`。
- 复杂业务流程放入 `Application` 服务，不要堆在 Controller 中。
- 领域实体和规则变多后，可新增 `Domain` 目录或拆出独立项目。

不要放：

- 前端页面代码。
- AI 模型文件。
- `bin`、`obj`、`.vs` 等 IDE 或编译生成物。

## ai

AI 推理服务源码目录。

```text
ai/sam-inference
├─ app
│  ├─ __init__.py
│  └─ main.py
├─ Dockerfile
├─ requirements.txt
├─ requirements-docker.txt
└─ .dockerignore
```

用途：

- `app/main.py`：SAM 推理 API、分割、overlay 和 mask 相关逻辑。
- `requirements*.txt`：Python 依赖。
- `Dockerfile`：推理服务镜像构建。

不要放：

- `sam3.pt` 模型本体。模型统一放在 `资源/模型`。
- Python 缓存目录 `__pycache__`。
- 推理输出的大量临时文件。

## legacy

历史代码备份目录。

```text
legacy
├─ static-frontend
└─ python-api
```

用途：

- `static-frontend`：旧版原生 HTML/CSS/JS 前端。
- `python-api`：旧版 Python API。

约定：

- 当前主线开发不再修改这里。
- 需要参考旧逻辑时可以查看。
- 确认长期不需要后，可以整体删除。

## 与根目录的关系

```text
项目根目录
├─ src      代码
├─ 文档      产品、设计、说明文档
├─ 资源      模型、原型图、素材
└─ docker-compose.yml
```

简单规则：

- 能编译、能运行、能部署的代码放 `src`。
- 给人看的说明、设计、产品资料放 `文档`。
- 图片、模型、原型图、素材放 `资源`。
- 临时产物、构建产物、缓存文件不要保留。
